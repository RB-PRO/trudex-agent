# Подготовка окружения для обогащения лидов

Два сценария. Выбери свой.

## Сценарий А. Чат-агент (Kimi, Claude и т.п.) — рекомендуется

Ничего устанавливать не нужно. У агента уже есть веб-поиск, браузер и исполнение кода.

1. Создай рабочую папку, например `C:\leads\`.
2. Положи в неё три файла: `AGENTS.md`, `leads_schema.json`, `inn_list.txt` (список ИНН, один на строку).
3. В чате: «Работай по AGENTS.md из папки C:\leads\, входной файл inn_list.txt, результат положи туда же».
4. Получаешь `C:\leads\leads_result.json`. Его забирает VBA-надстройка.

Пропускная способность: ~100 ИНН за проход. Файлов больше 100 — режь на части и давай по очереди.

## Сценарий Б. Локальный скрипт по API (если захочешь без чата)

Минимум:
- Python 3.10+
- Пакеты: `requests`, `openpyxl` (только если нужен Excel на выходе)

```bash
pip install requests openpyxl
```

Структура:
```
C:\leads\
  inn_list.txt        # вход: ИНН, один на строку
  leads_result.json   # выход: пишется инкрементально
  leads_schema.json   # контракт
  AGENTS.md           # методология (для агента-оператора)
```

Переменная окружения `KIMI_API_KEY` (или аналог выбранного провайдера). Запуск — ручной или планировщик Windows: раз в день проверять `inn_list.txt`, если появился новый — обрабатывать и переименовывать в `inn_list.done.txt`.

Важно: автономный скрипт без чата покрывает шаги 1, 3 и частично 2 (агрегаторы часто блокируют прямой HTTP — тогда выручка только из РФСД). Шаги 4–5 (банкротство, сайт) надёжнее всего работают через чат-агента с веб-поиском. Поэтому основной режим — Сценарий А, скрипт — опциональный бэкенд для выручки.

## Замечания для VBA-стороны

- Читать JSON как UTF-8. В VBA: `ADODB.Stream` с charset «UTF-8».
- `null` в JSON → пустая ячейка.
- Имена полей — латиница (`inn`, `director_last`, `revenue_2021`...), кириллица в ключах не используется — меньше проблем с кодировками.
